# AkShare 行情数据导入设计

## 目标

Issue 03 为固定的 20 只 A 股建立 PostgreSQL 数据模型，并提供可重复运行的数据导入流程。行情由 AkShare 获取，数据库结构通过 Alembic 迁移管理。应用和导入命令不得在运行时创建或修改表。

本设计只覆盖数据模型、迁移和导入，不实现 FastAPI 行情接口、前端、实时轮询或历史回放。

## 已确认范围

- 股票池固定为 `config/stock_pool.csv` 中的 20 只股票。
- CSV 是股票基础资料的唯一来源；AkShare 只提供行情。
- 日线导入必须显式传入 `--start-date` 和 `--end-date`，使用不复权数据。
- 分钟数据固定为 1 分钟、不复权；从 AkShare 可返回的近期数据中选择 20 只股票都有记录的最新共同交易日。
- 如果近期范围内没有共同分钟交易日，导入失败并列出缺失股票，不填补缺失行情。
- 已有复合主键的行情记录在重复导入时跳过，不覆盖旧值。
- 任一股票的请求、字段规范化或数据校验最终失败时，数据库事务整体回滚。
- 每只股票的网络请求最多重试 2 次；超过次数后失败。
- 不引入备用数据源、Redis、微服务或 WebSocket。

## 数据来源与字段

### 日线

使用 AkShare `stock_zh_a_hist_tx`（腾讯数据接口），传入带市场前缀的固定股票代码、明确的开始和结束日期，以及 `adjust=""`。将英文返回字段规范化为交易日期、OHLC、成交量和成交额。

### 分钟线

使用 AkShare `stock_zh_a_minute`（新浪数据接口），频率固定为 `period="1"`，`adjust=""`，再按请求窗口过滤。该接口只提供近期 1 分钟数据，因此本项目不承诺全历史分钟线。

分别获取股票池各股票的近期结果，取 20 只股票共同有行情记录的最新日期。若找不到共同日期，失败并报告无数据或缺少该日记录的股票。只保存接口实际返回的分钟记录，不合成休市、午休、停牌或缺失时点。

AkShare 字段名、代码转换、成交量单位和数值精度在实现时以固定 fixture 及一次真实接口检查核实。若接口返回单位与数据库约定不同，必须在规范化层显式转换并在学习记录中说明。

## 数据模型

### `stocks`

- `symbol`: 股票代码，主键。
- `name`: 股票名称，非空。
- `sector`: 固定股票池中的行业，非空。
- `source_industry`: 来源行业，非空。
- `exchange`: 交易所代码，非空。
- `list_status`: 上市状态，非空。

导入时根据 CSV 同步股票资料。允许更新股票名称、行业、交易所和状态，以 CSV 为准；不得增加 CSV 之外的股票。

### `daily_quotes`

- `symbol`: 外键引用 `stocks.symbol`。
- `trade_date`: 交易日期。
- `open`, `high`, `low`, `close`: `NUMERIC(18, 4)`。
- `volume`: `BIGINT`。
- `amount`: `NUMERIC(20, 2)`。
- 复合主键：`(symbol, trade_date)`。

### `minute_quotes`

- `symbol`: 外键引用 `stocks.symbol`。
- `trade_time`: 分钟时间，数据库类型为不带时区的 timestamp，项目统一按北京时间解释。
- `open`, `high`, `low`, `close`: `NUMERIC(18, 4)`。
- `volume`: `BIGINT`。
- `amount`: `NUMERIC(20, 2)`。
- 复合主键：`(symbol, trade_time)`。
- 不重复保存 `trade_date`；按 `trade_time` 查询交易日。

两张行情表均要求行情字段非空，价格大于零，最高价不低于最低价，成交量与成交额非负。复合主键同时提供按股票和日期/时间查询的索引，不额外建立重复索引。

## 迁移和配置

- 使用 SQLAlchemy 2.x 声明式模型描述表结构。
- 使用 Alembic 版本迁移创建表、键、约束和索引。
- 迁移由开发者显式运行 `uv run alembic upgrade head`。
- 应用和导入命令不调用 `Base.metadata.create_all()`，也不执行 DDL。
- 迁移与导入共用 `app/db.py` 的配置读取：自动读取项目根目录 `.env`，终端环境变量优先；优先使用 `DATABASE_URL`，未设置时从完整的 `POSTGRES_*` 配置生成本地连接串。凭据不写入源码或迁移文件。
- 使用 `pyproject.toml` 和 `uv` 管理依赖。

## 导入命令与事务

日线命令 `daily` 要求 `--start-date` 和 `--end-date`，日期必须有效且开始日期不晚于结束日期。分钟命令 `minute` 使用 `--lookback-days` 指定近期窗口，默认 5 天。两个命令的股票池路径均默认是 `config/stock_pool.csv`。

导入步骤：

1. 校验 CSV 的必需列、20 个唯一股票代码和每行业数量约束。
2. 根据命令类型，通过 AkShare 适配器获取所有股票在指定范围的日线或近期 1 分钟数据。
3. 分钟导入计算最新共同交易日，只保留该日实际存在的记录。
4. 规范化字段并检查必需列、空结果、重复行和基础数值约束。
5. 每个命令分别使用一个 PostgreSQL 事务同步 `stocks` 并写入对应的日线或分钟线；两个命令之间不共用事务。
6. 对已存在的复合主键使用跳过策略，不更新已有行情。
7. 输出股票数、对应行情实际新增行数和日期范围；分钟命令另输出共同交易日。

每个命令的所有网络获取和数据规范化均在数据库事务开始前完成；数据库写入阶段任一错误均回滚本次命令的全部写入，避免部分股票已写入而命令失败。某个命令失败不回滚另一个命令之前已提交的数据。获取失败最多重试 2 次，最终错误包含股票代码和数据类型。

## 代码边界

- `app/db.py`: 统一读取环境变量和项目 `.env` 的数据库配置，创建 SQLAlchemy engine。
- `app/import_service.py`: 校验股票池、协调行情获取与规范化、选择共同分钟日期，并管理写入事务和导入报告。
- `app/models.py`: 声明式模型、约束和索引定义。
- `app/data_provider.py`: AkShare 网络请求及有限重试。
- `app/normalizers.py`: AkShare 返回值到统一行情记录的转换与校验。
- `scripts/import_market_data.py`: 参数解析、创建 provider 和 session factory、调用导入服务并输出结果报告。
- `alembic/`: 显式数据库迁移。
- `tests/`: 本地 fixture 单元测试及 PostgreSQL 集成测试。

AkShare 适配器不访问数据库；规范化逻辑不发网络请求；导入服务协调这些边界，命令行入口负责配置和调用。

## 验证

- 本地 fixture 测试字段映射、日期解析、错误字段、空结果、基础数值规则和共同分钟日期选择。
- Docker PostgreSQL 集成测试迁移、外键、检查约束、事务回滚和重复导入跳过行为。
- 测试不调用真实 AkShare 网络。另运行一次显式的真实接口检查，记录接口字段和成交量单位。
- 验收迁移重复运行安全，且运行时导入路径没有建表逻辑。

## 已知限制

- AkShare 依赖外部网站，接口可能变化或暂时不可用；有限重试后命令明确失败。
- 1 分钟数据只有近期窗口，不支持全历史分钟查询。
- AkShare 返回的成交量单位、数据精度及代码格式必须在实施验证中确认，不能仅凭接口名称推断。
- “共同分钟日期”要求固定的全部 20 只股票都有实际记录；停牌或无记录的股票会导致该日期不合格，不补造数据。
