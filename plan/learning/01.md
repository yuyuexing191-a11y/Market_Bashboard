## issue: 任务单
标题：补充项目介绍
目标：
让别人知道这个项目是做什么的。
要做的修改：
在什么上面做修改
验收：
验收标准是什么


## branch：给这次修改创建一个开发分支
- `git switch -c docs/project-introduction`
    git switch：切换分支。
    -c：创建一个新分支。
    docs/project-introduction：你给分支起的名字
- `git branch --show-current`：检查现在的分支

## 编辑文件
- `git status`:哪个文件上的改变
- `git diff`:具体上的修改

## 提交步骤
- `git add .`:加入更改的所有文件
- `git commit -m "docs: explain project purpose"`:提交更改的说明
    commit：注释规范
    feat：新增功能
    fix：修复bug
    docs：修改文档，readme
    refactor：代码重构
    perf：性能优化
- `git push -u origin docs/project-introduction`
    push：上传提交
    origin：远端仓库的简称，通常就是你这个 GitHub 仓库
    docs/project-introduction：要上传的分支
    -u：记住本地分支与远端分支的对应关系

## PR：请求把开发分支的修改合入 main
修改内容：
在文件中补充项目用途。

检查：
已阅读差异，确认只修改了项目介绍。

**Closes**合并后自动关闭 issue`Closes #12`
**Fixes**修 bug，自动关 issue`Fixes #12`
**Resolves**解决，自动关 issue`Resolves #12`
**Refs**仅关联，不自动关`Refs #12`
**Related to**提到相关 issue`Related to #8`
