# Issue 03：数据模型与 AkShare 导入记录

## 启动数据库

先复制 `.env.example` 为 `.env`，确认 `POSTGRES_DB`、`POSTGRES_USER`、
`POSTGRES_PASSWORD` 和 `DB_PORT`，再启动当前项目自己的 PostgreSQL 卷：

```bash
docker compose up -d --wait
```

应用连接通过 `DATABASE_URL` 环境变量提供。表结构必须先执行迁移：

```bash
# 当前 shell 临时加载 .env，并拼出应用使用的连接串
set -a
source .env
export DATABASE_URL="postgresql+psycopg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:${DB_PORT:-5432}/${POSTGRES_DB}"
set +a

uv run alembic upgrade head
```

导入命令不会运行建表 DDL。股票池固定读取 `config/stock_pool.csv` 的 20 只股票。

`DATABASE_URL` 必须存在于当前 shell 环境中。`.env.example` 只是示例文件，
`uv` 和 Alembic 不会自动读取 `.env`；如果新开了终端，需要重新执行上面的
`set -a` 到 `set +a` 命令。缺少它时会看到：

```text
RuntimeError: 未设置 DATABASE_URL
```

## 代码架构

```text
config/stock_pool.csv
        -> scripts/import_market_data.py
        -> app/data_provider.py       调用 AkShare
        -> app/normalizers.py          字段转换和数据校验
        -> app/import_service.py       事务写入和重复跳过
        -> PostgreSQL
```

- `stocks` 保存 20 只股票基础资料。
- `daily_quotes` 保存日线数据，唯一键是 `(symbol, trade_date)`。
- `minute_quotes` 保存分钟数据，唯一键是 `(symbol, trade_time)`。
- Alembic 只负责建表和迁移；导入命令不会运行 `CREATE TABLE`。
- AkShare 请求和规范化完成后才开始数据库事务，失败不会留下半批数据。

## 导入行情

日线必须显式传入日期范围：

```bash
uv run python scripts/import_market_data.py daily \
  --start-date 2024-01-01 --end-date 2024-01-31
```

分钟线默认请求最近 5 天窗口，从 20 只股票都有数据的日期中选择最近一天：

```bash
uv run python scripts/import_market_data.py minute --lookback-days 5
```

命令输出股票数、新增行数和日期范围。重复的复合主键会跳过；网络请求或字段校验失败会使本次导入失败。

## 验证

```bash
uv run pytest -q
```

本次实现使用 AkShare 的腾讯不复权日线接口和新浪 1 分钟接口，价格、成交量和成交额在写入前校验；数据库结构由 Alembic 迁移创建，当前迁移头为 `002_drop_quote_indexes`。不同接口返回的英文列名由 `app/data_provider.py` 转换为统一字段。

## 查询导入结果

```bash
set -a
source .env
set +a

docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "SELECT count(*) AS stocks FROM stocks;"
docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "SELECT count(*) AS daily_quotes FROM daily_quotes;"
docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "SELECT count(*) AS minute_quotes FROM minute_quotes;"
docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "SELECT min(trade_date), max(trade_date), count(DISTINCT symbol) FROM daily_quotes;"
docker compose exec -T postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "SELECT min(trade_time), max(trade_time), count(DISTINCT symbol) FROM minute_quotes;"
```

本次实际导入后的结果是：`stocks=20`、`daily_quotes=8514`、`minute_quotes=4760`。
日线实际交易日期为 `2025-01-02` 到 `2026-10-09`；分钟数据覆盖
`2026-10-09` 一个共同交易日。请求范围的首尾日期如果是周末或节假日，返回结果不会补造数据。

## AkShare 网络错误排查

如果看到下面的错误：

```text
RemoteDisconnected: Remote end closed connection without response
```

这表示 AkShare 上游接口关闭了连接，不是 PostgreSQL 迁移错误。当前适配器使用：

- `stock_zh_a_hist_tx`：腾讯日线接口；
- `stock_zh_a_minute`：新浪分钟接口；
- 日线请求超时为 20 秒，每只股票最多重试 2 次。

遇到网络错误时，先只测试一只股票，不要重复连续导入：

```bash
uv run python - <<'PY'
import akshare as ak

df = ak.stock_zh_a_hist_tx(
    symbol="sh601318",
    start_date="20250101",
    end_date="20261010",
    adjust="",
    timeout=20,
)
print(len(df), df.columns.tolist())
PY
```

单只股票成功后，再运行 20 只股票的导入命令。导入失败时，程序会在数据库事务开始前中止，
不会写入半批行情。
