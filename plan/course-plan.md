# 股票行情实时查看器 ·开发课程设计

## 课程目标

以「AI 驱动开发（vibe coding）」的流程规范性为核心训练目标。

结业应具备：
- 能把模糊想法拆成可执行的 GitHub Issue（含验收标准、任务拆解）
- 能基于 Issue 用 AI 完成开发，过程中提交可读的 commit，最终提出描述清楚的 PR
- 能回应 review 意见并修改，走 PR 合入而非直接 push main
- 能交付一个能跑起来的 Web 产品，且对 AI 生成的工程细节有自己的判断（性能、可维护性）

## 技术栈

- **Python 主线**
- **Rust 热点模块**
- **PostgreSQL**：Docker Compose 环境
- **前端Web**
- **数据源**：AkShare（固定股票池，HTTP 获取，不引入 WebSocket）

## 项目形态

- 单人项目，个人仓库(github)
- 统一主题
- 从零搭建骨架，不设 CI，无分支保护，无组织
- 时间不设限，每环节跑通为止

## 流程红线

- main 分支禁止直接 push（约定 + review 时发现纠正）
- AI 不发起 PR、不 merge——这两个动作必须手动完成

## 验收框架

### 流程规范性（50%）
- Issue 是否闭环（每个 Issue 有验收标准、有对应 PR、有关闭记录）
- commit 是否可读、是否分逻辑拆步
- PR 是否描述清楚、是否回应 review 意见
- 是否全程没有直接 push main（可查 git 历史验证）

### 产品效果（50%）
- 产品能跑起来（Docker 一条命令启动）
- 功能是否达到上述功能清单
- PostgreSQL 数据模型是否合理（有迁移、有索引、没有随手建表）
- 是否体现「自己的判断」——如 Rust 热点模块的优化、某处为什么这么设计


## 实施节奏（弹性）

1. **Git 基础关**：手写完整 git 流程，不用 AI
2. **环境搭建**：Docker Compose 拉起 PostgreSQL
3. **从零搭骨架**：Python 后端 + Rust 模块 + PostgreSQL 连通
4. **数据获取**：使用 AkShare 获取固定股票池数据，规范化后落库；实时更新采用 HTTP 轮询
5. **功能开发**：按功能清单拆 Issue，逐项开发提 PR
6. **前端呈现**：Web 看板（技术栈自选）
7. **验收**：功能清单 + 数据抽点核对 + 现场答辩
