# 股票行情实时查看器：Issue 规划

本文将 `plan/course-plan.md` 中的课程目标拆成 17 个可执行 Issue。课程计划是需求材料；本文件记录讨论后确认的实施顺序。每个 Issue 对应一次主要交付和一次 PR，Issue 内部再列学习步骤。

## 已确认的边界

- 学习者：个人从零完成项目；前端 Issue 内部解释 React、TypeScript、Vite 和 ECharts 概念。
- 硬性要求：Python、Rust、PostgreSQL、Web 前端，以及人工发起和合入 PR。
- 市场：A 股；股票池约 20 只，覆盖金融、消费、制造、医药、科技等行业，并固定在项目配置中。
- 数据源：只读 `/mnt/glusterfs/quantdata/tushare/` 下的本地 Parquet；不假定已有 Tushare 在线 API 权限。
- 导入范围：20 只股票的全部可用日线历史；分钟线第一阶段只导入最新可用的完整交易日，后续再扩展多日。
- 分钟数据：只按实际存在的行情记录计算，不把休市、午休、停牌或缺失记录补成零价格。
- 后端：FastAPI + PostgreSQL；前端：React + TypeScript + Vite + Apache ECharts。
- 指标：收盘价 MA、成交量均线、涨跌幅。窗口不足时返回空值；涨跌幅按连续两条实际记录计算。
- Rust：先编译独立命令验证输入输出，再封装为 Python 扩展；Rust 与 Python 使用同一组数据核对结果。
- 实时行情：先验证数据源是否持续更新；没有实时源时使用明确标注的历史回放，不能把静态历史数据称为实时。

## Issue 清单

### Issue 01：手动完成一次 Git 分支与 PR 流程

- 前置：无。
- 学习内容：分支、提交、PR、review、merge。
- 交付：一次文档变更的分支、可读提交、PR、人工 review 和合入记录。
- 验收：没有直接向 `main` 提交；能解释每个 Git 动作的目的。

### Issue 02：项目文档与开发约定

- 前置：Issue 01。
- 学习内容：README、启动说明、检查命令、学习记录和中文文档约定。
- 交付：README、开发约定和学习记录结构。
- 验收：新参与者能根据文档知道如何开始、如何验证和如何按 Issue 工作。

### Issue 03：数据源确认与股票池配置

- 前置：Issue 02。
- 学习内容：Parquet、分区数据集、OHLCV 字段、可复现配置。
- 交付：记录 `stock_list`、`stock_daily_kbar`、`stock_1min_kbar` 的字段和分区方式，并配置 20 只覆盖金融、消费、制造、医药、科技的 A 股。
- 验收：20 只股票在 `stock_list` 中存在、上市状态正常，日线和分钟数据可查；能说明分钟数据按 `date=YYYY-MM-DD` 分区。

### Issue 04：Docker 与 PostgreSQL 环境

- 前置：Issue 02。
- 学习内容：容器、服务、健康检查和环境变量。
- 交付：PostgreSQL 容器、健康检查和连接配置。
- 验收：一条命令启动数据库；客户端可以连接；容器重启后服务仍可用。

### Issue 05：Python、Rust、前端项目骨架

- 前置：Issue 04。
- 学习内容：FastAPI 项目、Rust 命令行项目、React + TypeScript + Vite 项目、依赖管理和开发服务器。
- 交付：三部分项目骨架，以及 FastAPI 数据库健康检查接口。
- 验收：三部分都能独立启动或编译；接口能返回服务和数据库状态；数据库断开时返回明确错误。

### Issue 06：数据库模型与迁移

- 前置：Issue 03、Issue 04。
- 学习内容：迁移、主键、唯一约束、外键和索引。
- 交付：股票表、日线行情表、分钟行情表、迁移脚本和查询索引。
- 验收：迁移可重复执行；重复行情不能重复插入；按股票和时间范围查询有索引。

### Issue 07：日线与单日分钟线导入

- 前置：Issue 03、Issue 06。
- 学习内容：批量导入、幂等性、分区读取、命令参数和日期筛选。
- 交付：一个可重复运行的导入命令：导入 20 只股票全部可用日线历史，并默认导入最新可用完整交易日的分钟线；支持参数指定其他日期。
- 验收：重复执行不会重复插入；分钟线只包含指定日期的实际记录；没有数据时给出明确提示；导入数量与源文件抽样一致。

### Issue 08：数据质量检查

- 前置：Issue 07。
- 学习内容：数据校验、抽样核对、异常检测和失败退出。
- 交付：检查股票数量、日期范围、重复记录、空值和异常价格的命令。
- 验收：输出可读报告；发现错误时命令失败，而不是静默通过。

### Issue 09：Rust 指标命令

- 前置：Issue 05。
- 学习内容：命令行接口、JSON、数据契约、向量、窗口计算、浮点数和边界条件。
- 交付：Rust 独立命令，定义输入 JSON、输出 JSON 和错误格式，并实现 MA、成交量均线和涨跌幅。
- 验收：MA 和成交量均线使用简单移动平均；涨跌幅使用 `(本周期收盘价 / 上一周期收盘价 - 1) × 100%`；窗口不足返回空值；非法输入有明确错误。

### Issue 10：Python 对照测试与 Rust 扩展

- 前置：Issue 09。
- 学习内容：参考实现、数值误差、对照测试、语言互操作和错误传递。
- 交付：Python 参考实现、同一组样例数据的对照测试，以及可导入的 Rust Python 扩展。
- 验收：Python、Rust 命令和 Rust 扩展的结果在允许误差内一致；边界情况有测试；独立命令仍可运行。

### Issue 11：行情查询 API

- 前置：Issue 05、Issue 06、Issue 07。
- 学习内容：FastAPI 路由、响应模型、JSON、查询参数、时间范围和错误响应。
- 交付：股票列表、日线查询和分钟线查询接口。
- 验收：股票列表只返回固定股票池；日线支持全部历史；分钟线支持选定交易日；非法股票、日期和空结果有明确响应。

### Issue 12：指标 API

- 前置：Issue 10、Issue 11。
- 学习内容：服务层、指标调用、响应组合和接口边界。
- 交付：后端调用 Rust Python 扩展并返回指标数据的接口。
- 验收：API 结果与 Rust 独立命令一致；能说明数据查询、指标计算和响应组装分别发生在哪一层。

### Issue 13：React 核心行情看板

- 前置：Issue 11。
- 学习内容：React 组件和属性、TypeScript 类型、Vite 开发服务器、异步请求、加载/错误状态，以及 ECharts 数据转换、时间轴和提示框。
- 交付：股票选择、日期选择、API 请求、日线 K 线和单日 1 分钟 K 线页面。
- 验收：切换股票或日期会重新请求数据；响应类型有 TypeScript 定义；日线和分钟线 OHLC 映射正确；悬浮提示和缩放可用；空数据、加载失败和缺失分钟记录有清晰显示。

### Issue 14：指标、搜索与排名

- 前置：Issue 12、Issue 13。
- 学习内容：受控组件、条件渲染、派生状态、筛选、排序和图层配置。
- 交付：MA、成交量均线和涨跌幅开关，以及按代码/名称搜索、按涨跌幅/成交量排序。
- 验收：指标可分别显示或隐藏；搜索结果正确；排序口径写入接口说明；空结果有明确显示；图表结果与 API 数据一致。

### Issue 15：实时验证与历史回放

- 前置：Issue 07、Issue 08、Issue 13。
- 学习内容：文件更新时间、增量数据、实时性证据、定时器和播放状态。
- 交付：检查本地数据是否持续更新的报告；若没有实时源，实现按分钟顺序播放指定交易日数据的历史回放模式。
- 验收：明确判断本地数据是否可作为实时源；无实时源时页面明确标注“历史回放”；播放顺序正确；暂停和重新播放可用；不把静态历史数据称为实时。

### Issue 16：多日分钟线扩展

- 前置：Issue 07、Issue 15。
- 学习内容：日期范围导入、批量任务、查询性能和数据边界。
- 交付：可配置日期范围的分钟数据导入和查询能力。
- 验收：不破坏单日模式；导入可重复；查询不会混淆不同交易日；缺失记录仍按实际数据处理。

### Issue 17：完整系统启动与最终验收

- 前置：Issue 12、Issue 14、Issue 16。
- 学习内容：多服务编排、启动顺序、配置注入、Issue/commit/PR/review/merge 证据和设计权衡。
- 交付：数据库、后端、前端的一条命令启动方案；功能 Issue、对应 PR、review 意见和关闭记录；数据模型、Rust 选择、性能对照、已知限制和实时性结论说明。
- 验收：按 README 能启动并访问页面；每个功能 Issue 有对应 PR 和关闭记录；能解释关键设计、指标口径、Rust 与 Python 的边界，以及历史回放和真实实时数据的区别。

## 执行规则

1. 每个 Issue 开始前先读目标、前置条件和验收标准。
2. 每个 Issue 使用独立分支，提交可读 commit，通过人工 PR 和 review 后合入。
3. AI 可以协助分析、实现和解释，但不代替人工发起 PR 或合入 `main`。
4. Issue 完成后保留运行结果、测试结果或数据核对记录，作为课程流程证据。
5. 本文件不创建 GitHub Issue；确认后再按顺序复制到 GitHub Issues。
