# 股票行情实时查看器

## 先记住 5 条铁规矩

1. **永远不要直接往 `main` 推代码。** 每次都是：开分支 → 提交 → 提 PR → 网页上点 Merge。
2. **AI 不能帮你点「创建 PR」和「Merge」。** 这两步必须你自己在 GitHub 网页上点。
3. **每做一个功能，先开 GitHub Issue。** Issue 里必须写清楚：要做什么、怎样算做完。
4. **commit 要能看懂。** 一次只做一件事，例如 `feat: 增加股票列表接口`，不要写成 `update`，commit之间要问我的意见，描述问题要用中文。
5. **把怎么运行的内容写在plan/learning的文件夹下面** 不要readme,`plan/learning/xx.md` = 个人学习、踩坑、命令记录（本地仓库文档），记录这部分是怎么启动怎么运行的，不要洗的太过于复杂。

## 已确认的边界
- 学习者：个人从零完成项目；前端 Issue，在对话中内部解释 React、TypeScript、Vite 和 ECharts 概念。
- 市场：A 股；股票池约 20 只，覆盖金融、消费、制造、医药、科技等行业，并固定在项目配置中。
- 数据源：使用 Python AkShare 获取行情；日线使用腾讯接口、分钟线使用新浪接口；不依赖 Tushare Token。
- 导入范围：固定 20 只股票的指定日期范围日线，以及最近一个交易日的分钟线。
- 分钟数据：只按实际存在的行情记录计算，不把休市、午休、停牌或缺失记录补成零价格。
- 后端：FastAPI + PostgreSQL；前端：React + TypeScript + Vite + Apache ECharts。
- 指标：收盘价 MA、成交量均线、涨跌幅。窗口不足时返回空值；涨跌幅按连续两条实际记录计算。
- Rust：先编译独立命令验证输入输出，再封装为 Python 扩展；Rust 与 Python 使用同一组数据核对结果。
- 实时行情：通过 HTTP 轮询验证 AkShare 是否能持续返回更新数据；不可用时使用明确标注的历史回放，不能把静态历史数据称为实时。

### Issue 03：数据模型与数据导入

要做：

- 获取固定股票池指定日期范围的日线；分钟线只获取最近一个交易日。
- 将 AkShare 字段转换为数据库字段，检查股票池、必需字段、重复记录和空结果。

验收：
- [ ] 通过迁移文件创建股票、日线和分钟行情表；重复执行迁移不会重复建表或破坏数据，运行时不执行 `CREATE TABLE`。
- [ ] 表具有主键、外键、唯一约束和按股票及时间查询所需的索引；唯一约束阻止重复行情。

- [ ] 日线导入覆盖命令指定的日期范围，分钟线只包含最近一个交易日实际返回的记录，不补零价格；无数据时明确提示。
- [ ] 导入后能输出股票数量、日线/分钟行数和日期范围，抽样字段与 AkShare 规范化结果一致。

### Issue 05：行情 API、指标计算与指标 API

目标：提供能查询行情并返回正确指标的后端服务。

前置：Issue 03、Issue 04。

要做（按顺序）：

验收：

## 执行规则

1. 每个主 Issue 内部用任务清单拆步骤，可分多次可读 commit，不为每个小步骤另建 Issue。
2. 每个主 Issue 使用独立分支，通常对应一个主要 PR；PR 发起和合入由人手动完成。
3. 自查明确标注作者身份，检查结果与实际执行一致。
4. 教学笔记沿用 plan/learning/01.md 的简短形式：概念、命令、参数解释和示例。
5. 已完成的旧任务不重做；按合并关系复用证据，只补主任务中未完成的部分。已有学习笔记保留原编号，新笔记注明主任务与原步骤的对应关系。
6. 旧 Issue 未完成时，在 GitHub 记录其并入的主任务链接再关闭，说明“任务合并”，不能写成“实现完成”。已关闭的旧任务保留完成记录。
7. 本次更新本地规划，不自动创建、修改或关闭 GitHub Issue；实际任务状态以 GitHub 为准。
