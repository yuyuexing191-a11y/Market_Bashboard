# 股票行情实时查看器：Issue 规划

将原 17 个细分任务合并为 7 个主 Issue。每个主 Issue 交付一个完整阶段，内部步骤使用任务清单，不再为每个学习概念单独创建 Issue。

本文件中的编号是课程序号，不是 GitHub 编号；发布或关联任务时使用 GitHub 实际编号。原有学习记录继续保留，不代表合并后的整个阶段已经完成。

## 已确认的边界

- 学习者：个人从零完成项目；前端 Issue 内部解释 React、TypeScript、Vite 和 ECharts 概念。
- 硬性要求：Python、Rust、PostgreSQL、Web 前端，以及人工发起和合入 PR。
- 市场：A 股；股票池约 20 只，覆盖金融、消费、制造、医药、科技等行业，并固定在项目配置中。
- 数据源：只读 `/mnt/glusterfs/quantdata/tushare/` 下的本地 Parquet；不假定已有 Tushare 在线 API 权限。
- 导入范围：20 只股票的全部可用日线历史；分钟线第一阶段只导入最新可用的完整交易日，后续再扩展多日。
- 分钟数据：只按实际存在的行情记录计算，不把休市、午休、停牌或缺失记录补成零价格。
- 后端：FastAPI + PostgreSQL；前端：React + TypeScript + Vite + Apache ECharts。
- 指标：收盘价 MA、成交量均线、涨跌幅。窗口不足时返回空值；涨跌幅按连续两条实际记录计算。
- Rust：先编译独立命令验证输入输出，再封装为 Python 扩展；Rust 与 Python 使用同一组数据核对结果。
- 实时行情：先验证数据源是否持续更新；没有实时源时使用明确标注的历史回放，不能把静态历史数据称为实时。

### Issue 02：数据源与数据库环境

目标：确认项目用什么数据，并启动可连接的数据库。

前置：Issue 01。

要做：
- 确认 stock_list、stock_daily_kbar、stock_1min_kbar 的字段、路径和分区方式。
- 固定 20 只当前上市、流动性较高的 A 股，金融、消费、制造、医药、科技各 4 只。
- 数据源笔记保留在 plan/learning/03.md，股票池配置使用 config/stock_pool.csv。
- 用 Docker Compose 启动 PostgreSQL，配置环境变量、健康检查和持久化存储。

验收：
- [ ] 20 只股票在 stock_list 中存在、上市状态正常，日线和分钟数据可查。
- [ ] 能解释 Parquet、OHLCV 和 date=YYYY-MM-DD 分区。
- [ ] 一条命令启动数据库，客户端能连接，健康检查正确。
- [ ] 容器重启后仍可连接，持久化数据保留。

### Issue 03：数据模型与数据导入

目标：把源文件中的行情可靠地导入 PostgreSQL，并验证导入结果。

前置：Issue 02。

要做：
- 建立股票、日线、分钟行情表及迁移，设计主键、唯一约束、外键和查询索引。
- 建立 Python 导入命令所需的最小依赖环境；完整应用骨架在 Issue 04 完成。
- 导入股票池全部可用日线历史；分钟线默认导入最新可用完整交易日，也能指定日期。
- 检查股票数量、日期范围、重复、空值和异常价格，抽样核对源文件。

验收：
- [ ] 迁移重复运行不会重复建表或破坏数据；按股票和时间查询有索引。
- [ ] 唯一约束阻止重复行情，导入命令重复运行不会重复插入。
- [ ] 分钟线只包含指定日期的实际记录，不补零价格；无数据时明确提示。
- [ ] 导入数量及抽样字段与源文件一致。
- [ ] 质量检查输出可读报告，发现错误时以失败状态退出。

目标：让后端、Rust 和前端工程能独立运行，并打通后端数据库连接。

前置：Issue 02；推荐在 Issue 03 后执行。

要做：

- 复用 Issue 03 的 Python 环境和数据访问代码，统一依赖与配置。
- 实现服务与数据库健康检查接口，记录启动和编译命令。

验收：
- [ ] 后端与前端能启动，Rust 工程能编译运行。
- [ ] 健康接口能返回服务和数据库状态。
- [ ] 数据库断开时返回明确错误。

### Issue 05：行情 API、指标计算与指标 API

目标：提供能查询行情并返回正确指标的后端服务。

前置：Issue 03、Issue 04。

要做（按顺序）：
- 实现股票列表、日线范围查询和指定交易日分钟查询 API。
- 定义 Rust 命令的输入 JSON、输出 JSON 和错误格式，计算收盘价 MA、成交量均线和涨跌幅。
- 写 Python 参考实现，用相同样例对照 Rust，再封装可导入的 Rust Python 扩展。
- 后端查询行情、调用 Rust 扩展并组装指标响应。

验收：
- [ ] 股票列表只返回固定股票池；支持全部日线历史和选定交易日分钟线。
- [ ] 非法股票、日期、空结果有明确响应。
- [ ] MA 与成交量均线为简单移动平均，窗口不足返回空值。
- [ ] 涨跌幅按连续实际记录的 (本周期收盘价 / 上一周期收盘价 - 1) × 100% 计算。
- [ ] Rust 非法输入有明确错误；边界情况有测试，对照测试明确数值误差容限。
- [ ] Python、Rust 命令、Rust 扩展与 API 结果在允许误差内一致，独立 Rust 命令仍可运行。
- [ ] 能解释查询、计算和响应组装各自的职责。

### Issue 06：前端行情看板

目标：通过 Web 页面选择股票、查看 K 线与指标、搜索和排名。

前置：Issue 05。

要做：
- 使用 React、TypeScript 和 ECharts 实现股票与日期选择、异步请求、日线及单日分钟 K 线。
- 实现 MA、成交量均线和涨跌幅显示开关。
- 实现代码/名称搜索、按涨跌幅/成交量排名，记录排序口径。
- 处理加载、空数据、请求失败和缺失分钟记录。

验收：
- [ ] 切换股票或日期会重新请求，响应有 TypeScript 类型。
- [ ] OHLC 映射正确，悬浮提示和缩放可用，图表结果与 API 一致。
- [ ] 指标可分别显示或隐藏，搜索和排名结果符合说明中的口径。
- [ ] 加载、空结果和失败状态清晰，缺失记录不补零价格。

### Issue 07：实时回放与最终交付

目标：交付能启动、能演示、能解释数据实时性的完整产品。

前置：Issue 06。

要做：
- 通过文件更新时间和增量记录验证本地数据是否持续更新，记录实时性结论。
- 没有实时源时实现历史回放：按分钟播放、暂停和重新播放；页面明确标注。
- 扩展分钟线日期范围导入与查询，保留单日模式。
- 编排数据库、后端、前端，一条命令启动完整系统。
- 整理功能验收、数据抽查、设计说明和 Issue/commit/PR/自查/合入证据。

验收：
- [ ] 实时性结论有观察证据；静态数据不称为实时，无实时源时明确显示“历史回放”。
- [ ] 回放顺序正确，暂停和重新播放可用；有实时源时验证实际更新行为。
- [ ] 多日导入可重复，查询不混淆交易日，不破坏单日模式或补零价格。
- [ ] 按 README 一条命令启动完整系统并访问页面。
- [ ] 各主任务有对应 PR、自查及关闭记录；已完成的旧任务可作为阶段证据关联。
- [ ] 能解释数据库模型、指标口径、Rust/Python 边界、性能对照、已知限制与实时性结论。

## 执行规则

1. 每个主 Issue 内部用任务清单拆步骤，可分多次可读 commit，不为每个小步骤另建 Issue。
2. 每个主 Issue 使用独立分支，通常对应一个主要 PR；PR 发起和合入由人手动完成。
3. 自查明确标注作者身份，检查结果与实际执行一致。
4. 教学笔记沿用 plan/learning/01.md 的简短形式：概念、命令、参数解释和示例。
5. 已完成的旧任务不重做；按合并关系复用证据，只补主任务中未完成的部分。已有学习笔记保留原编号，新笔记注明主任务与原步骤的对应关系。
6. 旧 Issue 未完成时，在 GitHub 记录其并入的主任务链接再关闭，说明“任务合并”，不能写成“实现完成”。已关闭的旧任务保留完成记录。
7. 本次更新本地规划，不自动创建、修改或关闭 GitHub Issue；实际任务状态以 GitHub 为准。
